# 路由器兼容性与上游集成

本页记录当前源码的集成范围与截至 2026-11-02 的验证结果。主程序版本跟随官方 GUI 稳定版，核心和独立插件各自更新；版本号相同不表示与桌面版拥有完全相同的宿主能力。源码修复不会自动替换已经发布的二进制，发行包应以 Release 对应提交为准；发布与同版本更新方法见 [发布说明](releases/1.28.1.md)。

## 当前能力

- 保留配置、订阅、规则集、计划任务和核心管理；按官方操作方式恢复插件页、插件参数表单、规则类型与动作、页面可见性、核心临时设置及通用日志控制。
- 深浅主题、登录和安全页使用同一控件体系；手机调整导航、工具栏和弹窗排版。背景图片与外观偏好仅保存在当前浏览器，特性开关默认关闭。
- 访问密码支持旧密钥迁移、PBKDF2、可选 TOTP、一次性恢复码与会话撤销；凭据原子保存，读取或写入失败不放行认证。
- 独立插件中心提供 14 个职责分离的插件：1 个订阅整理、10 个配置生成、3 个手动诊断。中心只读取元数据，明确选择安装或更新才下载校验源码；不随主程序打包插件，不发行六个旧独立包。
- 新配置默认 TUN 与协议探测，关闭 mixed 入站；默认六个远程规则集每 24 小时更新，单项下载出站留空并继承默认 HTTP 客户端。程序内置完整的初始规则，使新配置和相同默认来源的旧配置不依赖首次下载；核心继续管理更新和缓存，显式设置及自定义规则来源不被替换。
- OpenWrt 使用 procd 管理，其他系统使用对应服务管理器；Linux amd64、arm64、armv7、mips、mipsle 静态发布。容器支持 IPv6 监听、持久数据卷和额外启动参数。

原版与网络设备适配差异见 [GUI 操作逻辑对照](gui-parity.md)，插件接口与迁移见 [插件说明](plugins.md)，部署要求见 [路由器说明](routers.md)。

## 修复与性能改进

| 范围 | 当前行为 |
| --- | --- |
| 配置与节点身份 | 不同订阅的同名节点使用稳定唯一标签，组成员和节点引用同步改写；空 DNS 解析器字段省略，禁止 FakeIP 作为 DNS final |
| 订阅与规则集刷新 | HTTP 状态、大小、完整读取及脚本处理成功后再保存；元数据写入失败恢复旧缓存，手动订阅脚本同步保存实际节点 |
| 并发编辑 | 订阅节点与修订号保持一致；资源事件遗漏后补拉完整列表，保存失败保留草稿，快速保存和切换标签保留最后输入 |
| JavaScript | 旧订阅/配置脚本和插件执行均有时限、取消与栈限制，隔离输入；保留返回新值或原地修改的用法，拒绝无效结果 |
| 流与预览 | WebSocket 回调隔离旧连接并限制入站消息；离开概览后释放专属流；规则集反编译支持取消并限制为 15 秒、32 MiB 预览 |
| 更新与进程 | 下载及安装串行化，取消完全结束后才释放任务；校验摘要与候选程序后替换，准备失败保留旧程序；回收 Unix 更新助手 |
| 核心与缓存 | 运行中的同分支须先停止再更新；清理共享缓存依据实际运行快照；重启失败尝试恢复上次成功实例，显式停止优先 |
| 规则启动与失败处理 | 六份初始规则在核心检查前校验并按需原子恢复；准备失败保留运行中的核心，下载错误或代理挂起不阻碍默认规则启动；修复停止初始化时误报崩溃的竞态 |
| 网络设置与页面切换 | 采用官方分段请求代理、点击编辑和下载加速开关，服务环境代理作用于部署设备；修复下拉定位，空插件页刷新保留现有内容 |
| 认证与隐私 | 凭据 JSON 拒绝重复字段及大小写别名；限制认证资源；订阅成功日志与错误结果不暴露 URL 凭据、路径或查询参数 |
| 调度与资源 | 五/六字段 cron 语义一致，日期跳转取代逐秒扫描；缓存备份优先保留 inode，避免将旧缓存全部载入内存；移除重复初始请求 |
| 构建与依赖 | Release、CI 和容器统一 Node 24；锁定修补后的依赖，保持锁文件和工作区配置一致 |

缓存恢复不提供跨文件断电事务保证。Goja 的执行时限和数据大小限制不是强内存隔离，应只运行可信脚本。手动诊断可访问管理员指定的内网地址，不是任意不可信代码的网络沙箱。

## 上游移植

保留的官方改进包括下载流式 SHA256 校验、按核心版本处理 TUN stack、Windows 控制台编码回退、HTML/表格内容净化、IME 输入保护、多关键词规则集搜索、异步格式化时的输入与多选区保护、出站排序使用最新订阅名称，以及 DNS 乐观缓存的配置和互斥校验。

Web 服务已有的 sing-box 1.14 配置迁移、DNS 响应规则、HTTP 客户端、直接入站和经认证的原生 API 就绪检查继续沿用。没有引入 Wails 窗口、托盘、桌面系统代理、系统 DNS 权限、Windows 提权或桌面文件管理；后端操作始终作用于部署 WebUI 的设备。

官方 100 个插件入口按真实依赖审核后选择、合并或改写，未将桌面常驻服务逐项复制。命名/去重/筛选统一为订阅节点整理，出口/IP/连通性统一为网络诊断；透明代理、DNS 和客户端策略分别负责独立职责。AdGuardHome、FRP 等进程仍交给 procd/systemd，插件不安装或管理这些服务。

OpenWrt 虚拟机采用四个模拟 CPU、512 MiB RAM 和独立 NAT，验证 procd、认证、TOTP、防重放、恢复码、会话轮换及重启后凭据状态；插件覆盖 14 项目录、29 组 Goja 向量和 10 项真实核心配置检查。插件测试进程使用 `GOMAXPROCS=1`，生产执行限额不变，QEMU 耗时不是实机性能基准。

尚未验证 GL-MT3600BE 实机、MTK 硬件加速、无线、厂商 VPN、多 WAN 和真实多客户端吞吐量。隔离 DNS 测试能复现错误 DNS 地址导致规则/全局路径差异，不能单独确认用户 `google.com` 故障由 AdGuard Home 引起；原生 DNS 可用仍需结合实际 DNS 路径、规则命中和策略组选择分析。复审不连接路由器，也不操作用户正在运行的桌面 GUI。

复现入口：

```sh
pnpm --dir frontend test
pnpm --dir frontend build
go run ./tests ./... -count=1 -timeout=180s
# 需要支持 race 的平台及 C 编译器
go run ./tests -race -short ./... -count=1 -timeout=180s
```

真实核心与独立插件测试的环境变量见 [测试说明](../tests/README.md)。测试仅使用临时目录和隔离端点，不能指向生产 `data/`。
