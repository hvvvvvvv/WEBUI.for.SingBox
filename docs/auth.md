# 安全

认证设置独立于通用设置，位于「设置 → 安全」。登录页与设置表单支持深色、浅色、跟随系统及窄屏。主题偏好在登录前加载，输入框、错误状态和按钮使用对应配色。

## 密码与两步验证

新安装保持原先的未配置状态。先设置独立的访问密码；网页设置的新密码至少 15 个字符，最多 1,024 个 UTF-8 字节，支持空格和中文。升级前已设置的短密钥仍可登录，不会因为新规则锁定管理员。

TOTP 为可选第二因素，不会因升级自动启用：

1. 在「安全」中输入当前密码，选择「设置验证器」。
2. 用验证器应用扫描二维码，或手动输入密钥，选择基于时间、6 位、30 秒。二维码在当前浏览器本地生成，不使用外部二维码网站。
3. 输入验证器产生的验证码，验证通过后才启用。
4. 将显示的十个一次性恢复码存到独立安全位置，确认保存。关闭页面后不再显示；已启用的 TOTP 密钥也不会再次读取。

登录需要密码和验证码，或密码和一个未用过的恢复码。每个 TOTP 时间步只能成功使用一次；刚启用或刚登录后，同一组验证码不可立即再次使用，请等下一组。路由器与手机需保持时间同步，允许相邻一个 30 秒时间步的误差。认证不会替用户修改路由器时间或 NTP 设置。

关闭 TOTP、重生成恢复码或修改密码需要当前密码，以及已启用的第二因素。变更会撤销其他会话并轮换当前会话；重新生成恢复码会作废全部旧码。移除访问密码前需先关闭 TOTP，并显式确认。

远程访问仍应使用 HTTPS 反向代理或可信 VPN；TOTP 不替代传输加密。登录失败有每来源地址及全账号的短期限流。反向代理部署时来源地址可能为代理本身，多个浏览器会共享此来源限额；不信任客户端任意提供的转发头来绕过限流。

## 存储、恢复与升级

凭据继续保存在程序目录下的 `data/secret.key`。旧 SHA256 密钥在成功登录后迁移为带随机盐的 PBKDF2-HMAC-SHA256（600,000 次）；TOTP 状态和恢复码摘要与密码同文件提交，使用受限权限、临时文件、同步与原子替换。一次性验证码的消费在颁发会话之前持久化，重启不能重放已消费的验证码或恢复码。磁盘读取失败、损坏或持久化失败不会放行认证。

丢失验证器时，先使用密码与恢复码登录并重新配置。两者均无法恢复时，具有设备本地管理权限的管理员可以停止 WebUI 服务后执行：

```sh
./webui.for.singbox --reset-auth-stdin
```

从标准输入提供新密码并结束输入；该模式避免密码进入命令参数。输入本身是否回显由终端控制，应使用受控终端或受限密码文件输入，避免保存在共享终端记录或脚本中。本地重置会清除 TOTP 和旧恢复码，再启动服务后可使用新密码登录。命令需要获得数据目录的实例锁，运行中的 WebUI 必须先停止；其他配置损坏不会阻止只处理凭据的恢复。`--reset-auth clear` 是显式关闭认证，只适用于受控的本地恢复，不是日常登录方法。

备份需要包含 `data/secret.key`，并按敏感数据保管。恢复旧备份会恢复当时的密码、TOTP 密钥及恢复码消费状态，应随后更换验证器/恢复码。仅支持旧共享密钥的版本不能读取当前凭据格式；回滚应恢复匹配的程序和数据备份。损坏文件、重复 JSON 字段和字段大小写别名均会被拒绝，不会降级为无认证访问。

实现及回归依据：[RFC 4226](https://www.rfc-editor.org/rfc/rfc4226)、[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)、[OWASP 密码存储指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
